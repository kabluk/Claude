# Califormis

Веб-приложение для самостоятельной подготовки судебных форм по разводу в
Калифорнии. На текущем этапе — **каркас и навигация** (без бизнес-логики).

> ⚖ **Califormis** — это software для самостоятельной подготовки документов.
> Мы не предоставляем юридических консультаций. Информация ≠ юридический совет.

## Стек

- React 18 + React Router 6
- Vite 5
- Чистый CSS (дизайн-система в `src/styles.css`), без UI-библиотек
- Собственная i18n без зависимостей (Context + localStorage)
- Хранение данных на клиенте (localStorage), без бэкенда

Дизайн вдохновлён референсом юридического лендинга Veritas Law Firm:
глубокий тёмно-синий фон, тёплый золотой акцент, серифные заголовки.

## Мультиязычность (i18n)

- Языки: **English** (по умолчанию), Español, Русский, 中文, Tiếng Việt
- Селектор в шапке: флаг (inline SVG) + родное название; выбор сохраняется
  в `localStorage` (`califormis.lang`) и переживает перезагрузку
- Переводятся UI, вопросы визарда и объяснения полей
- **Судебные формы остаются на английском** — коды и названия форм
  (FL-100…), названия округов и юридические термины не переводятся; данные
  пользователя подставляются в англоязычную форму как есть
- На каждом экране — сноска: «Формы подаются на английском. Перевод дан для
  вашего понимания.»

Все строки — в `src/i18n/translations.js`; провайдер и хук `useI18n()` — в
`src/i18n/I18nContext.jsx`.

## Хранение данных

Данные хранятся локально (localStorage) — отдельный слой репозитория без
бэкенда. Сущности:

| Сущность    | Поля                                                |
| ----------- | --------------------------------------------------- |
| **User**    | `email`, `county`, `language`                       |
| **Case**    | `type`, `has_children`, `status`, `wizard_step`     |
| **Answer**  | `case_id`, `field_key`, `value`                     |
| **Payment** | `case_id`, `amount`, `status` (пока всегда `unpaid`)|

- **Autosave**: ответы визарда сохраняются по мере ввода (`Answer` по
  `field_key`); позиция в визарде (`wizard_step`) тоже сохраняется — при
  возврате прогресс не теряется
- Выбор типа дела, округа, наличия детей и e-mail пишутся сразу при изменении
- Для каждого дела создаётся `Payment` со статусом `unpaid` (платёжного
  потока пока нет)
- Текущие `User` и `Case` связаны через запись `session`

Слой: `src/data/storage.js` (низкоуровневый localStorage),
`src/data/repository.js` (сущности и CRUD), `src/state/AppState.jsx`
(React-контекст, хук `useAppState()`, autosave).

## Визард: сценарий «Развод по согласию, есть дети, Los Angeles»

Экран 3 — структурированное интервью под этот сценарий (`src/screens/Wizard.jsx`):

- **Секции**: А) Стороны (Petitioner/Respondent: имя, адрес, дата брака,
  дата разъезда) · Б) Дети (имя, дата/место рождения, пол + история
  проживания за 5 лет: период, город/штат, с кем жил, кем приходится) ·
  В) Имущество и долги (активы по категориям, долги) · Г) Доходы и расходы
  (для алиментов и FL-150) · Д) Согласие супруга (имя и подпись респондента
  для waiver) · Е) Проверка.
- **Подсказки**: у каждого поля иконка «?» (`components/HelpTip.jsx`) с
  простым объяснением и примером — переведены на все 5 языков.
- **Повторяемые группы**: несколько детей, у каждого — несколько периодов
  проживания; список активов и долгов (добавить/удалить).
- **Autosave**: скалярные поля — отдельные `Answer`; коллекции (дети с
  вложенной историей, активы, долги) — JSON в одном `Answer`. Позиция
  (`wizard_step`) сохраняется — возврат продолжает с той же секции.
- **Готовность**: пройдя все секции, пользователь попадает в «Проверьте
  данные» — сводка по всем секциям (пустые поля помечены «—»).
- Сценарий (тип дела · дети · округ) показан чипами вверху из сохранённых
  данных. Остальные экраны не затронуты.

## Калькулятор child support (Family Code §4055)

Экран 4 (`src/screens/Calculator.jsx`, формула — `src/data/childSupport.js`):

- **Формула-гайдлайн** Калифорнии: `CS = K × [HN − H% × TN]`, множитель для
  нескольких детей по §4055(b)(4). Суммы трактуются как чистый месячный
  располагаемый доход.
- **Входы**: доход каждого родителя в месяц, timeshare (% времени с истцом),
  число детей. Поля прифиллятся из визарда (доходы, число детей).
- **Выход**: кто платит, итог в месяц и сумма на каждого ребёнка, K-фактор и
  сама формула (для прозрачности расчёта).
- **Дисклеймер под результатом**: «Это арифметический расчёт по официальной
  формуле, а не рекомендация. Итоговую сумму определяет суд.» Никаких советов
  по сумме не даётся.
- Входы и результат сохраняются в **едином финансовом профиле дела**
  (`finance_profile` через `useAppState().updateFinanceProfile`), переживают
  перезагрузку. Переведено на все 5 языков.

## Движок заполнения судебных PDF

Переиспользуемый модуль (`src/pdf/`) заполняет **встроенные поля** официальных
fillable-PDF (AcroForm) через `pdf-lib` — текст по координатам не рисуется.

- `engine.js` — ядро: `loadPdf`, `listFields` (через `getFields`),
  `applyMapping` (field_key → имя поля PDF), `setFieldValues` (text/checkbox/
  dropdown/radio/optionlist с отчётом set/missing/skipped), `addDraftWatermark`,
  `fillPdf` (load → map → fill → watermark → save).
- `profile.js` — `buildCaseProfile`: единый плоский профиль дела из
  User/Case/Answers; **все итоги (активы, долги, расходы, алименты) считаются
  здесь, в приложении**, а не в форме.
- `forms.js` — реестр форм: `registerForm`/`getForm`/`listForms`,
  `inspectFormFields` (посмотреть имена полей), `fillForm` (заполнить
  зарегистрированную форму из профиля). Формы добавляются **по одной**.
- `selftest.js` — генерирует тестовый fillable-PDF и прогоняет через движок
  (тестовая загрузка одного PDF; конкретных форм пока нет).
- Водяной знак превью: «DRAFT — проверьте перед подачей» (Unicode-шрифт
  `public/fonts/DejaVuSans-Bold.ttf` для кириллицы).

Добавить форму: положить официальный PDF в `public/forms/`, посмотреть имена
полей через `inspectFormFields`, затем `registerForm({ id, title, url, mapping })`.

### Проверка актуальности форм

```bash
npm run check-forms
```

Скачивает текущую официальную версию каждой формы с `courts.ca.gov` и сверяет
её **SHA-256** с baseline (`sourceSha256` в FormTemplate). Хеш сменился ⇒ форму
перепубликовали: перекачать PDF в `public/forms/`, обновить `revision` и
`sourceSha256`, затем перепроверить маппинг полей (имена могли измениться).
Код возврата 1 при изменениях — удобно для CI. (Строку «Rev. …» в этих PDF
не прочитать автоматически — текст закодирован глифами, поэтому сверяем по
хешу источника.) Скрипт: `scripts/check-forms.mjs`.

### FL-100 (Petition) — первая форма

`src/pdf/fl100.js` + `src/pdf/counties.js`:

- **`buildFL100Profile`** — value-side профиль (логический `field_key` → значение)
  из данных визарда: шапка (стороны, суд из `CountyInfo`, `attorney_for="Self
  (Pro Per)"`, `petition_type`, `case_number` пусто), §1–§10 (relationship,
  residency, даты + авто-расчёт `time_married` годы/месяцы, таблица детей с
  возрастом, `grounds="Irreconcilable differences"`, custody, separate/community
  property, spousal support, restore name), подпись.
- **`computeTimeMarried`** — автоматический расчёт срока брака (годы/месяцы) из
  дат брака и разъезда.
- **`fl105Required`** — бизнес-правило: при несовершеннолетних детях в пакет
  обязательно добавляется FL-105 (показывается у кнопки в кабинете).
- **`FL100_TEMPLATE`** (FormTemplate): `revision: 'Rev. January 1, 2020'`
  (зафиксировано из футера формы), `mapping: FL100_MAPPING`. Зарегистрирована
  через `registerForm`.
- **`FL100_MAPPING`** — реальные имена полей PDF (извлечены через
  `inspectFormFields('FL-100')`, 158 полей, имена вида
  `FL-100[0].Page1[0].…`), сопоставленные с ключами `buildFL100Profile`.
  Неоднозначные чекбоксы разрешены по их `/TU` (tooltip). Один логический ключ
  может писать в несколько полей PDF (бегущая шапка сторон на каждой странице).
- Кнопка **«Сформировать FL-100 (DRAFT)»** в личном кабинете
  (`components/Fl100Generate.jsx`) — берёт данные дела, прогоняет через движок,
  отдаёт скачиваемый PDF с водяным знаком DRAFT.

> **Официальный PDF.** `public/forms/FL-100.pdf` — официальная форма
> FL-100 [Rev. January 1, 2020] с courts.ca.gov, **зафиксирована в репозитории**
> (не зависим от живого сайта суда). Файл нормализован для pdf-lib: снят слой
> XFA, отключены object streams (классический xref), выставлен `NeedAppearances`.
> Встроенные AcroForm-поля и содержимое сохранены.
>
> Движок (`loadPdf`) открывает permission-encrypted формы суда через
> `ignoreEncryption`. Все итоги (активы/долги/срок брака/возраст детей)
> считаются в приложении и подставляются как значения.

Доработки по ручной проверке:

- **§2 Residency** — выбор пользователя (Petitioner / Respondent / оба) в блоке
  генерации; по умолчанию отмечается **только Petitioner**. Галочки ставятся
  строго по факту (`residency_party`).
- **Даты** форматируются в **MM/DD/YYYY** перед записью (визард хранит ISO).
- **Суммы** — с разделителями тысяч (`$450,000`).
- **§10b** (`ListProperty_ft`) — уменьшен шрифт поля (`fontSizes`) и опущена
  верхняя граница (`rectAdjust`), чтобы текст не перекрывал печатную надпись
  «as follows (specify)» (проверено на флэттене). Движок поддерживает
  `fontSizes` и `rectAdjust` на уровне `fillPdf`/`fillForm`.

### FL-105 (UCCJEA) — вторая форма

`src/pdf/fl105.js` — официальная **FL-105/GC-120 [Rev. January 1, 2025]**,
зафиксирована в `public/forms/FL-105.pdf` (нормализована для pdf-lib: снят XFA,
классический xref, `NeedAppearances`). Реальные имена полей извлечены через
`inspectFormFields('FL-105')` (148 полей, имена вида `FL-105[0].Page1[0].…`).

- **`buildFL105Profile`** — заполняет: шапку (стороны, суд из `CountyInfo`,
  `case_number` пусто), §1 (заявитель — сторона дела), §2 (число детей + таблица
  имя/дата рождения/место рождения, до 4), §3 (история проживания за 5 лет —
  до 5 строк: From=дата начала, To=дата конца или «Present»; строится по
  ребёнку и не раньше его ДР — для общей таблицы клампится к ДР младшего;
  город-штат, с кем жил, кем приходится; шрифт адреса уменьшён), §4 (другие
  судебные дела — Yes/No + строка по типу: family/guardianship/other/juvenile/
  adoption), §6 (лица вне процесса — Yes/No + имя/адрес, тип притязания, ребёнок),
  подпись. Даты — **MM/DD/YYYY**; чекбоксы §4/§6 — **по умолчанию No**.
- **Единый источник детей.** Имена и даты рождения берутся из того же
  `children`-ответа, что и FL-100 → совпадают.
- **`fl105NeedsContinuation`** — если детей > 4 или истории проживания у детей
  различаются (одна таблица §3 не вмещает) → нужна continuation-копия (показ
  у кнопки).
- **Пакет.** Кнопка в кабинете генерит **FL-100 всегда**, а **FL-105 — только
  при наличии несовершеннолетних детей**, вместе, двумя PDF с водяным знаком.

### FL-110 (Summons) — третья форма

`src/pdf/fl110.js` — официальная **FL-110 [Rev. January 1, 2015]** (сверено
06/30/2026), зафиксирована в `public/forms/FL-110.pdf`. Полей мало — всё
переиспользуется из дела:

- NOTICE TO RESPONDENT / AVISO AL DEMANDADO → `respondent_name` (англ.+исп.);
- «Petitioner's name is» / «Nombre del demandante» → `petitioner_name`;
- «name and address of the court» (item 1) → блок из `CountyInfo`;
- «petitioner without an attorney» (item 2) → блок из структурного контакта
  (`buildPartyContact`: имя/адрес/телефон/email — единый источник, как у
  FL-100/FL-105);
- `case_number`, Date/Clerk/Deputy — пусто (заполняет суд).
- Статичный двуязычный текст уведомления и блок ATROS (стр. 2) **не трогаются**.
- В пакет **входит всегда** (и с детьми, и без).

### FL-150 (Income & Expense Declaration) — четвёртая форма

`src/pdf/fl150.js` — официальная **FL-150 [Rev. September 1, 2024]** (4 стр.,
266 полей), зафиксирована в `public/forms/FL-150.pdf`. **Полный маппинг всех
содержательных секций**, а не только шапка:

- **Шапка** (все 4 страницы): контакт из `buildPartyContact`, суд из
  `CountyInfo`, стороны, case number.
- **§1 Employment**: работодатель, адрес, телефон, должность, дата начала, часы
  в неделю, gross «per month». (Поле телефона имеет точку в имени —
  экранируется `\\.` для `getField`.)
- **§2 Age & education**: возраст, high school yes/no, годы колледжа.
- **§3 Tax**: год, статус (single/HoH/MFS/MFJ), штат (CA), exemptions.
- **§4** оценка дохода второй стороны (`respondent_income`).
- **§5 Income** (колонка *Average monthly*): зарплата, overtime, commissions,
  public assistance, spousal/partner support, pension, SS, disability,
  unemployment, workers' comp, other — построчно.
- **§6 Investment income**, **§7 Self-employment**.
- **§10 Deductions** (строки a–g → L1–L7 по порядку; L5 несёт чекбокс
  «federally tax deductible» = строка e «spousal support»).
- **§11 Assets**: cash, stocks, all other property (real/personal чекбоксы).
- **§13 Expenses** — построчно (13a Home с под-строками rent/mortgage,
  property tax, insurance, maintenance; 13b–13q), **итог 13r TOTAL считается
  в приложении** + чекбокс «Actual expenses».
- **§16–17 Child support**: число детей, тайм-шер %% (из `finance_profile`),
  наличие/компания/стоимость страховки детей.
- Подпись (дата + печатное имя).

Источник данных — единый: калькулятор/`finance_profile`, ответы `children`/
`assets`, плюс JSON-ответ `fl150_profile` для секций, которые соберёт будущая
секция визарда (employment, разбивка доходов/расходов, страховка детей);
отсутствующие значения просто остаются пустыми. **Все итоги (расходы) считаются
в приложении**, не в форме. Воспроизводимая проверка fill + read-back по всем
страницам: `node scripts/demo-fl150.mjs`. В пакет входит всегда.

### FL-140 (Declaration of Disclosure) — пятая форма

`src/pdf/fl140.js` — официальная **FL-140 [Rev. July 1, 2013]** (1 стр., 36 полей),
зафиксирована в `public/forms/FL-140.pdf`. Это титульная декларация раскрытия:
данных мало, в основном чекбоксы. Маппинг:

- **Шапка** — единый источник, как везде: блок «party without attorney»
  (`PartyAttyAddInfo_ft` — имя + адрес многострочно), телефон/email, attorney for,
  суд из `CountyInfo`, стороны, case number.
- **Заголовок формы** — `disclosure_party` (Petitioner's/Respondent's) и
  `disclosure_type` (Preliminary/Final) — чекбоксы; по умолчанию Petitioner +
  Preliminary.
- **Приложенные документы** (пункты 1–6, имена полей сверены по Y-координате
  виджета): 1) FL-142 Schedule of Assets and Debts *или* FL-160 Property
  Declaration (+ Community/Separate); 2) FL-150 Income & Expense; 3) налоговые
  декларации за 2 года; 4) заявление о фактах оценки активов; 5) заявление об
  обязательствах общины; 6) раскрытие инвест-/бизнес-возможностей. По умолчанию
  отмечены FL-142 + FL-150 + 3/4/5/6 (полный комплект preliminary); переопределяется
  через JSON-ответ `fl140_profile`.
- **Подпись** — дата + печатное имя.

**FL-140 ВРУЧАЕТСЯ второй стороне и НЕ подаётся в суд** (на самой форме крупный
баннер «DO NOT FILE…»). В суд подаётся только FL-141, подтверждающий вручение.
Это отражено в кабинете (`cabinet.disclosureNote`, на всех 5 языках). В пакете
FL-140 идёт вместе с FL-150 (раскрытие финансов); FL-142 указана в списке, но
ещё не привязана. read-back: `node scripts/demo-fl140.mjs`.

### FL-142 (Schedule of Assets and Debts) — шестая форма

`src/pdf/fl142.js` — официальная **FL-142 [Rev. July 1, 2025]** (4 стр., 132 поля),
зафиксирована в `public/forms/FL-142.pdf`. Это **полный перечень** активов и долгов
(FL-150 несёт лишь сводку из 3 корзин). Маппинг:

- **Шапка** — единый источник: блок «party without attorney» (имя+адрес),
  телефон, attorney for, округ суда (на FL-142 в шапке только county), стороны,
  case number. `disclosure_party` (Petitioner's/Respondent's) — чекбокс.
- **Активы, 16 категорий** (1 недвижимость … 16 прочее): описание, S/P (P/R для
  раздельной), дата приобретения, текущая рыночная стоимость, сумма долга/
  обременения. **Итог активов (item 18) считается в приложении** (сумма стоимостей
  + сумма долгов отдельными колонками).
- **Долги, 6 категорий** (19 студенческие займы, 20 налоги, 21 алиментные
  задолженности, 22 необеспеченные займы, 23 кредитки, 24 прочее): кредитор,
  S/P, сумма (total owing), дата. **Итог долгов (item 26) считается в приложении.**
- **Подпись** — дата + печатное имя.

Роли колонок читаются **по /TU-подписям, а не позиционно**: порядок полей в форме
непоследователен (item 2 «мебель» перевёрнут; в items 4 и 11 колонка «долг» — это
`TextField5`). Конфиг категорий в модуле кодирует выверенное соответствие
роль→поле. На форме **одна строка на категорию**: если записей больше, они
сворачиваются в строку (подытог + склеенные описания) и ставится флаг
continuation (`fl142NeedsContinuation`, item 27) — итоги всегда считаются по всем
записям.

**Согласованность с FL-150**: корзины сверяются один-в-один — сумма
savings+checking = FL-150 §11a, stocks = §11b, недвижимость (net) = §11c; данные
из одного источника (`fl142_profile` + `fl150_profile.assets` + `a.assets`).

**FL-142 ВРУЧАЕТСЯ второй стороне и НЕ подаётся** (на форме баннер «THIS FORM
SHOULD NOT BE FILED WITH THE COURT»). В пакете идёт с FL-140 + FL-150 (раскрытие).
read-back: `node scripts/demo-fl142.mjs`.

### FL-141 (Declaration re Service of Disclosure) — седьмая форма (подаётся!)

`src/pdf/fl141.js` — официальная **FL-141 [Rev. July 1, 2013]** (1 стр., 56 полей),
зафиксирована в `public/forms/FL-141.pdf`. **В отличие от FL-140/142/150, эта
форма ПОДАЁТСЯ в суд** — она подтверждает, что документы раскрытия были вручены
(или что раскрытие отменено). Финансовых данных не несёт — только шапка и
чекбоксы вручения/отказа. Маппинг:

- **Шапка** — единый источник (party-блок, телефон/email, суд, стороны).
- **Заголовок** — чьё (Petitioner's/Respondent's, радиокнопка 1/2) и какое
  (Preliminary/Final) раскрытие.
- **Item 1** — «I am the … petitioner/respondent» (для pro per — petitioner).
- **Item 2 (preliminary)** — чей preliminary + кому вручён (другой стороне/её
  адвокату) + как (лично/почтой) + дата.
- **Item 3 (final)** — то же для финального, если он вручался.
- **Item 4 (отказ)** — раскрытие отменено: 4a взаимный отказ по FC §2105(d)
  (+ FL-144, подаётся одновременно), 4b добровольный отказ по §2107, 4c
  default по §2110.
- **Подпись** — имя + дата.

Плоская модель данных (ключи, которые соберёт будущая секция визарда):
`disclosure_party`, `prelim_disclosure_served` + `prelim_served_date`,
`final_disclosure_served` + `final_served_date`, `final_disclosure_waived`,
`petitioner_printed_name`, `signature_date` (плюс `petition_date` для клампа).
Даты вручения **не могут быть раньше даты подачи петиции** — при необходимости
подтягиваются к ней. Сценарий по умолчанию (развод по согласию): истец вручил
**preliminary** второй стороне почтой, **final** взаимно отменён по §2105(d) с
FL-144 одновременно. `fl141_profile` остаётся необязательным override.

**Связка с FL-144**: `fl141AddsFl144(state)` возвращает `true`, когда финальное
раскрытие отменено (§2105(d)) — в этом случае в пакет добавляется FL-144
(Stipulation and Waiver of Final Declaration of Disclosure; форма пока не
привязана). FL-141 относится к **Стадии завершения** (с FL-180/FL-190) и в
стартовый пакет подачи не входит. read-back: `node scripts/demo-fl141.mjs`.

### FL-180 (Judgment) — восьмая форма (Стадия завершения)

`src/pdf/fl180.js` — официальная **FL-180 [Rev. July 1, 2012]** (2 стр., 116 полей),
зафиксирована в `public/forms/FL-180.pdf`. Это итоговое **решение суда**. Сам
FL-180 почти не содержит условий — он фиксирует тип/основание решения и
**ссылается на приложения-ордера** (FL-341 опека, FL-342 алименты на детей,
FL-343 супружеская поддержка, FL-345 имущество). Маппинг:

- **Шапка** — единый источник, как в FL-100 (party-блок, телефон/email, суд
  полностью, стороны); на стр. 2 «CASE NAME» = «истец / ответчик». `attorney_for`
  = «Self (Pro Per)».
- **Тип решения** — Dissolution (чекбокс в заголовке) + дата прекращения брачного
  статуса (`marital_status_end_date`, дублируется в п. 4a «status ends on»).
- **Основание (п. 2)** — default / uncontested / by-declaration (FC §2336) /
  contested / agreement; по умолчанию для uncontested — «Default or uncontested»
  + «By declaration under FC 2336» (безслушательный путь).
- **Восстановление девичьей фамилии (п. 4f)** — `restore_former_name` + `former_name`
  (те же ключи, что на FL-100 — единый источник).
- **Дети (п. 4i)** — при наличии детей: чекбокс «The children … are» + имена и
  даты рождения (из единого источника с FL-105/FL-150; ячейки многострочные, по
  ребёнку на строку).
- **Юрисдикция (п. 3)** — по умолчанию 3a «respondent was served with process».
- **Супружеская поддержка (п. 4l, обязательна в решении)** — `spousal_support_type`:
  назначена → 4l(3) «as set forth in FL-343» (+ FL-343 в пакете); отложена →
  4l(1) reserved (обе стороны); прекращена → 4l(2) terminated (обе стороны). Для
  uncontested по умолчанию — reserved (не лишает суд юрисдикции по ошибке).
- **Чекбоксы приложений (стр. 2, ключевое)** — по фактам дела: дети →
  `attach_fl341` + `attach_fl342` (+ уведомление FL-191/192 на стр. 1); раздел
  имущества → `attach_fl345`; супружеская поддержка (если назначена) →
  `attach_fl343`. Каждый флаг отмечает и строку «ordered as set forth in
  attached», и подчекбокс конкретной формы. «Number of pages attached» считается
  в приложении.
- **Подпись** — дата.

Дат брака/развода на FL-180 **нет** (они живут на FL-100); единственная дата —
прекращение статуса. **Без соответствующих приложений (FL-341/342/343/345) судья
FL-180 не подпишет** — это отражено в PLAN. FL-180 относится к **Стадии
завершения** дела (вместе с FL-190 и FL-141) и НЕ входит в стартовый пакет
подачи, поэтому кнопка генерации стартового пакета его не выдаёт. read-back:
`node scripts/demo-fl180.mjs`.

### FL-190 (Notice of Entry of Judgment) — девятая форма (Стадия завершения)

`src/pdf/fl190.js` — официальная **FL-190 [Rev. July 1, 2026]** (1 стр., 46 полей),
зафиксирована в `public/forms/FL-190.pdf`. Подаётся вместе с FL-180; клерк
возвращает её с датой внесения. Маппинг:

- **Шапка** — единый источник (в этой ревизии отдельные поля Name/Street/City/
  State/Zip/Phone/Email), суд, стороны. Внимание: в подписи сторон «Respondent 1»
  = `Party3` (Party2 — это «Petitioner 2»).
- **Тип решения** — Dissolution (совпадает с FL-180).
- **Effective date of termination of marital status** — из того же источника, что
  дата прекращения статуса на FL-180.
- **Mailing-адреса обеих сторон** — блоки «name and address» петиционера (из
  профиля) и респондента (если адрес есть) для рассылки заверенных копий.
- **Дата внесения, штамп клерка, certificate of mailing — ПУСТЫЕ** (заполняет
  суд при внесении/рассылке).

Стадия завершения (с FL-180/FL-141), в стартовый пакет не входит. read-back:
`node scripts/demo-fl190.mjs`.

### Контактный блок заявителя — структурно и единым источником

Адрес заявителя хранится **отдельными полями**: `party_street`, `party_city`,
`party_state`, `party_zip`, `party_phone`, `party_email` (собираются в секции
«Стороны» визарда). Общий билдер `src/pdf/party.js#buildPartyContact` —
**единый источник**: и FL-100, и FL-105 заполняют шапку из него одинаково. В
caption-маппинге: street→STREET ADDRESS, city→CITY, state→STATE, zip→ZIP CODE,
phone→TELEPHONE NO., email→EMAIL ADDRESS; STATE BAR / FIRM NAME / FAX — пустые.
Новые формы пакета подключают тот же билдер и получают тот же контакт.

## Экраны и сквозной прогресс

Сквозной индикатор «Шаг X из 6» отображается в шапке и в верхней навигации
на каждом экране. Маршруты заданы в `src/data/steps.js`.

| Шаг | Маршрут        | Экран                                                 |
| --- | -------------- | ----------------------------------------------------- |
| 1   | `/`            | Выбор типа дела (по согласию / спорный / алименты)    |
| 2   | `/county`      | Округ (dropdown) + переключатель «несовершеннолетние» |
| 3   | `/wizard`      | Визард-интервью с под-шагами и прогресс-баром         |
| 4   | `/calculator`  | Калькулятор алиментов (заглушка)                      |
| 5   | `/preview`     | Превью пакета форм + кнопка оплаты                     |
| 6   | `/cabinet`     | Личный кабинет: PDF, инструкция, чек-лист             |
