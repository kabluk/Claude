# Конвейер проекта: от идеи до шлифовки

Канонический порядок шагов для каждого нового проекта. Дополняет
PROJECT-PLAYBOOK.md (правила) — здесь ЧТО и КОГДА, там ПОЧЕМУ.

## Шаг 0 — Поиск идеи (в песочнице kabluk/claude)
Скилл find-niche: свип ниш, живые данные спроса (DataForSEO), Blue Ocean
Score. Выход: 2–3 кандидата с цифрами.

## Шаг 1 — Проверка кандидата (ДО «берём»)
- Домен: скриптом (RDAP) И глазами в браузере. Урок D-012 (CarrierTruth):
  скрипт наврал, конкурент рендерился на клиенте — вскрыл скриншот.
- Тёзки в отрасли: почти одинаковое имя у живого конкурента = дисквалификация.

## Шаг 2 — «Берём» → отдельный РЕПОЗИТОРИЙ (не ветка!)
Урок D-001: три проекта в одном репо путали ветки/CI/кроны. Проект = репо.
В тот же час:
- купить домен;
- скопировать скелет docs/playbook/templates/ → docs/project/ (VISION,
  DECISIONS, BACKLOG, RISKS, HANDOFF), doctor.mjs, CLAUDE.md,
  .claude/commands/ с оркестратором;
- записать D-001 (имя+домен), D-002 (границы v1), D-003 (стек);
- подключить репо к Claude-коннектору СРАЗУ;
- завести секреты и деплой-кнопку (deploy.yml) СРАЗУ.
Отложенный бутстрап = треть сессии на доступы (измерено 20.08).

## Шаг 3 — Структура (оркестратор; сессия открыта НА репо проекта)
/project-orchestrator существует только внутри репо проекта — сессия не там
= команды нет (правило 7). Оркестратор ведёт: семантика по данным поиска →
схема данных с инвариантами в БД → артборды дизайна. Всё в docs/.

## Шаг 4 — Сборка MVP (деплой с первого дня)
Каждый кусок: сделал → локальная проверка → деплой кнопкой → smoke-check
по НОВОМУ поведению (правило 5). Деплой — привычка, не финал (правило 8).

## Шаг 5 — SEO включается, как только прод жив (НЕ «потом»)
Индексация — самый длинный таймер (6–12 мес); каждый день промедления
отнят у будущего трафика. Как только страницы настоящие:
- домен → Google Search Console (domain property, DNS-верификация);
- sitemap.xml подать; robots, canonical, JSON-LD, llms.txt;
- программная страница публикуется ТОЛЬКО с реальными данными (thin content).

## Шаг 6 — Деньги уровня 1 (на готовом каталоге)
Вейтлист (проверка спроса) → аффилиатки + FTC-раскрытие → дистрибуция
вокруг бесплатного инструмента → фиды. Подписку строить только по сигналу.

## Шаг 7 — Шлифовка (фоном, не «этапом в конце»)
Мелкий бэклог, грабли в docs, алерты на замороженные источники (D12-класс).

## Каждая сессия, на любом шаге
1. Имя = «Проект — сессия N» (set_session_title сразу).
2. Первая команда — doctor.
3. Прочитать DECISIONS (последние 5) + BACKLOG.
4. Работать.
5. Финал: обновить docs, закоммитить, HANDOFF = 5 строк-указателей.
