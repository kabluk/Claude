# Califormis — продукт

## Проблема
Развод в Калифорнии без адвоката = 14+ официальных форм, строгие требования суда,
страх «заполнить неправильно и получить отказ». Адвокат стоит $3 000–15 000.

## Пользователь v1
Житель Калифорнии, разводящийся сам (pro se), компьютерно-средний. Приоритетный
сегмент — **испаноязычные** (огромный недообслуженный рынок). Старт — **округ Los Angeles**.

## Ключевой сценарий
1. Выбор типа дела (развод по согласию / спорный / только алименты)
2. Округ + наличие детей → система определяет пакет форм
3. Визард-интервью: простые вопросы → маппинг в поля официальных форм
4. Объяснение каждого поля («?») + калькулятор алиментов (§4055)
5. Проверка полноты → оплата $99 → экспорт заполненного PDF-пакета
6. Инструкция по подаче для конкретного округа + чек-лист

**Критерий готовности:** пользователь скачивает корректно заполненный пакет своего
типа дела + инструкцию для своего округа.

## UPL-граница (критично)
- ✅ Можно: показывать официальные формы, объяснять поля, считать алименты по
  публичной формуле, проверять полноту, давать процедурную информацию по округу.
- ❌ Нельзя: рекомендации под конкретную ситуацию («вам стоит просить X»), выбор
  стратегии, суммы «под вас». Это legal advice = UPL.
- Дисклеймер на каждом экране: «информация ≠ юридический совет».
- ⚠️ TODO: проверить с CA-юристом необходимость LDA-регистрации (B&P §6400) для
  софт-модели.

## Пайплайн создания (методология)
Идея → **промпт-инжиниринг (PRD)** → **VIBECODE/Claude Code (софт)** → **FLOWSTATE (лендинг)** → связка.
Каждый этап отдаёт «передаточный артефакт» для следующего (PRD → feature-карта → launch-чеклист),
что защищает от застревания между стадиями.

## Движок заполнения PDF (архитектура)
- Официальный fillable PDF в `public/forms/` → `inspectFormFields(id)` → `registerForm({id,title,url,mapping})`.
- Единый «финансовый/деловой профиль» дела кормит все формы (один источник данных).
- Все итоги (активы, долги, расходы, алименты, equalization) считаются в приложении.
- Read-back: движок перечитывает готовый PDF и сверяет значения.
- Водяной знак «DRAFT — проверьте перед подачей» до оплаты.
- `FormTemplate` хранит `revision` + `last_checked` (проверка актуальности форм).
