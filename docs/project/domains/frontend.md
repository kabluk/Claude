## Фасеты `FilterableList` скрывают пустые чипы и показывают счётчики (2026-08-08)

Баг с прода: чипы услуг/стандартов/сертификатов рендерились из глобальных
таксономий (`SERVICES`/`STANDARDS`/`CERT_KINDS`) независимо от того, есть ли
под них агентства на конкретной странице — на `/france/` кликабельные чипы
«Section 508»/«BITV 2.0»/«ADA»/«VPAT / ACR»/«Monitoring» гарантированно давали
пустой список (0 агентств). Функция `facet(avail)`, уже прячущая пустые чипы,
была применена только к ценовым диапазонам — несогласованность, не задумка.

- **Единый порог видимости `>= 1`** для всех четырёх фасетов (было `> 1`
  только у цен) — переименована в `facetHidden`, применена к services/
  standards/certs/prices одинаково. Доступность считается по `items` (полный
  список страницы), НЕ по `shown` (текущий отфильтрованный результат) —
  иначе чипы исчезали бы по мере выбора других фильтров, что дезориентирует:
  пользователь должен видеть все потенциально доступные пути ДО клика, а не
  только то, что осталось после уже применённых фильтров.
- **Счётчик рядом с подписью** («Training 20», класс `.num` на числе,
  tabular-nums) — количество агентств страницы под этот фильтр, посчитано из
  `items` через `useMemo`-карты (`serviceCounts`/`standardCounts`/
  `certCounts`/`priceCounts`), ничего не захардкожено. Видимый текст обёрнут
  в `aria-hidden="true"`, а на самой кнопке — `aria-label="Training, 20
  agencies"` (полная форма, ед./мн. число через хелпер `agencyCount`):
  слитная строка «Training 20» без контекста непонятна на слух, а
  `aria-label` на кнопке — стандартный способ дать screen reader полную
  формулировку, не трогая логику `aria-pressed`.
- **Кнопка «Reset filters»** в пустом состоянии — добавлена, но только когда
  реально есть что сбрасывать (`hasActiveFilters`, включает и текстовый
  поиск, не только чипы): пустое состояние теперь достижимо только через AND
  между фасетами или search-текст (одиночные чипы с count=0 больше не
  существуют), и без выхода пользователь иначе должен вручную отжимать каждый
  чип. Настоящая `<button>` (не ссылка/div), `.btn-ghost` (существующий
  класс, не новый), сбрасывает все фасеты и `q`.

  Отдельно проверено: пустой результат через AND (гибридная комбинация) и

## Правовой контекст в отчёте — 2026-08-06 (D-032, D-033)

`ReportPage` показывает блок «Legal basis» под находкой об отсутствующем/неполном
заявлении о доступности. Две части, разные по природе:

1. **Данные из API** (`ScanFinding.jurisdictionNote`, ставит воркер) — конкретный
   закон юрисдикции. Сумма штрафа попадает в текст только если сверена с
   первоисточником (сейчас — только DE). До D-032 поле возвращалось API, но
   фронтенд про него не знал и молча ронял — фича была невидима две итерации.
2. **Константа в UI** (не данные из API) — факт гармонизации: требования едины
   по ЕС (EN 301 549), надзор — нет. Одинаков для всех юрисдикций, тащить через
   воркер незачем.

Формулировка сверена с текстом Directive (EU) 2019/882, не с пересказом: «одного
окна» как в GDPR ст. 56 в EAA нет, по ст. 21/23 каждая страна назначает свои
органы и проверяет услуги на своей территории. Владелец сознательно выбрал одну
честную строку вместо перечня применимых законов по каждому рынку — перечень из
12 статей читается как запугивание при нулевой доп. точности (находка та же),
R1. Контраст (amber-800 на amber-50) проверен разовым прогоном axe-core:
0 нарушений `color-contrast`; `/report/:id` в постоянный CI-аудит не входит —
требует id.

Селектор страны на `/scan` (D-032): по умолчанию «Detect from the domain» —
прежнее поведение, выбирать не обязательно. Подсказка честно называет
ограничение: выбор одной страны задаёт, о какой отчитаться, а не единственную
применимую.

## Подпись бейджа теперь зависит от декларанта (2026-08-06, D-042)

видит, кто именно назвал прюфера, до того как откроет документ.
