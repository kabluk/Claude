# Design — источник правды дизайн-системы AccessAtlas

Обновлено: 2026-08-08 (D-073 — тёмная тема убрана по прямому указанию
владельца; ранее в этот же день — CN-BRANDBOOK/D-072, применён brand book
владельца). Направляющие документы — `docs/project/BRAND_BOOK.md`
(извлечённая спецификация макетов) и `docs/project/DESIGN_CONSTITUTION.md`
(§3, §24–29, §37–38, §57). Реализация токенов — `src/styles.css` (`@theme`),
это единственное место, где значения живут в коде; здесь — их назначение и
правила.

**Тема — ТОЛЬКО светлая (D-073).** Сайт рендерит одну и ту же светлую палитру
токенов независимо от системной темы посетителя. Тёмная тема, введённая
CN-BRANDBOOK (D-072), реализована и работала полностью, но убрана в тот же
день прямым указанием владельца — реверс не «скрыт переключателем», а
буквально: значения токенов dark-темы удалены из `src/styles.css`, второй
проход `audit-own-a11y.mjs` по `emulateMedia({colorScheme:'dark'})` убран.
Конституция §28 сама формулирует «dark mode is optional, do not implement
merely because it looks modern» — поэтому реверс не противоречит принципам,
он их же и применяет. Если тёмная тема понадобится снова — это отдельное
будущее решение владельца, не автоматическое восстановление.

История: палитра первой системы (slate + индиго, D-063, 2026-08-07) —
**superseded** brand book (D-072); принципы D-063 (семантическая severity,
всегда видимый фокус, tabular-nums, контраст-гейт) действуют без изменений.

North star (§3): точность, сдержанность, иерархия, engineering feel.

## 1. Палитра

Система пар «цвет / on-цвет» (M3-подобная), ОДНА светлая тема (D-073). Значения
core-токенов — из макетов владельца, таблица в `BRAND_BOOK.md` (здесь не
дублируется). Правила:

- Компоненты стилизуются ТОЛЬКО токенами (`bg-surface-container-low`,
  `text-on-surface-variant`, `border-outline-variant`…). Прямые slate/gray/
  hex-классы запрещены.
- Роли нейтральных: `background` — фон страницы; `surface` — поля ввода;
  `surface-container-low` — карточки/панели; `surface-container` — chips-фоны,
  hover; `on-surface` — основной текст; `on-surface-variant` — вторичный текст
  и плейсхолдеры; `outline` — границы полей; `outline-variant` — границы
  карточек/разделители.
- Один акцент — `primary` (интерактив, бренд, фокус, ссылки). Вторичный тон
  поверхности — `secondary-container` (CTA шапки, chip-accent, CTA-панели).
  Severity НЕ красится акцентом.
- Логотип: `brand-plate`/`brand-glyph` (primary + белый) — глиф карты
  остаётся светлым.

### Severity — семантическая шкала сканера

1:1 со шкалой impact axe-core (`scanner.ts`) + success/info (§27). В макетах
шкалы нет (кроме error) — подобрана в тон и посчитана скриптом (scratchpad
`contrast-d072.mjs`): текст ≥ 4.5:1 на background, на surface/card и на своей
soft-подложке. Живой гейт — axe в `audit-own-a11y`.

| Severity | Text/soft/border |
|---|---|
| Critical | `#ba1a1a` / `#ffedea` / `#ffb4ab` |
| Serious | `#8f4c00` / `#ffeedd` / `#ffb875` |
| Moderate | `#6d5e00` / `#fff3c4` / `#d1c26d` |
| Minor | `#46464f` / `#f1edf0` / `#c7c5d0` |
| Success | `#1f6d42` / `#d9f4e1` / `#8fd6ab` |
| Info | `#4451c8` / `#e0e0ff` / `#a9b0f5` |

Правила severity (без изменений с D-063):
- Цвет никогда не единственный носитель смысла (§27): рядом всегда текстовая
  метка (`impactLabel`).
- Critical и Serious — разные оттенки (красный/оранжевый), различимо при
  большинстве форм дальтонизма.
- Ошибки форм — `--color-critical` + `role="alert"` + `font-medium`.
- Success — только заработанное состояние. Info — light-вариант чуть темнее
  primary (#4451c8), потому что сам primary не дотягивает 4.5:1 на своей soft
  `#e0e0ff` — посчитано, не на глаз.
- Amber-блоки правовой информации (legal-basis, D-035) — family `moderate`.

## 2. Типографика

- **Inter Variable** (self-hosted @fontsource) — гротеск. Brand book визуально
  называет «Geist», но код всех макетов — Inter; взят Inter (D-072).
- **JetBrains Mono Variable** (self-hosted @fontsource, D-072) — `--font-mono`:
  UI-лейблы label-md и код. Решение D-063/D-068 «кастомный моно не вводим»
  пересмотрено D-072 указанием владельца (brand book прямо требует пару).
- Type-scale — `BRAND_BOOK.md` §3: `.display` (hero) / `.h1` / `.h2` /
  body 16 / `text-sm` 14 / `.label` (12 mono 500 uppercase 0.05em).
  Иерархия — весом и отступом; новые кегли не заводить без записи здесь.
- **`tabular-nums` для всех чисел-метрик** (§25): класс `.num`.

## 3. Spacing и форма

- Ритм — сетка 4px; секции `mt-10`/`mt-12`; колонка `max-w-5xl`
  (`container-page`); текст `max-w-2xl`.
- Радиусы: CN-BRANDBOOK-V2 (2026-08-08) вернул дефолтную шкалу Tailwind v4
  без переопределений — `lg`=0.5rem (кнопки/поля, `.btn`/`.input`, БЕЗ pill),
  `xl`=0.75rem (чипы), `2xl`=1rem (карточки/панели). Строки выше про
  «sm/md/lg/xl своя шкала» и «pill-кнопки/чипы» — текст первой палитры
  (D-063), устарел этим переходом; актуальные значения и их обоснование —
  комментарий в `src/styles.css` над `@theme`.
- **Тени / elevation (CN-ELEVATION, 2026-08-20).** До этого узла в `@theme`
  не было НИ ОДНОГО токена тени — глубина держалась только границей (§24) и
  `.card` поднимал тень исключительно на `:hover`, то есть на мобильном (где
  hover не существует физически) карточки были плоскими всегда. Это была
  прямая причина жалобы владельца «чекеры лёгкие и непривлекательные».
  Три семантические ступени в `--shadow-*` (namespace Tailwind v4 → утилиты
  `shadow-card`/`shadow-card-hover`/`shadow-panel`/`shadow-hero`), каждая —
  два слоя (узкая контактная + широкая мягкая, низкая альфа), цвет —
  `rgb(28 27 29 / α)` от `--color-on-surface`, НЕ чистый чёрный/серый
  («тень как мягкий свет, не обводка», Apple-манера):
  - `.card` — тень в ПОКОЕ (`shadow-card`) + `shadow-card-hover` по
    наведению/фокусу; граница сохранена. Затрагивает ВСЕ карточки сайта
    (`.card` — общий примитив: главная, индекс гайдов, индекс чекеров,
    отчёты, «другие чекеры»), не только 9 чекеров — намеренно, .card один
    компонентный класс на весь сайт.
  - `.panel` (новый класс) — оборачивает интерактивную часть каждого из 9
    бесплатных чекеров под `/checkers/`. `bg-surface-elevated` (белая,
    приподнятая ступень поверх `background`/`surface-container-low`) + тень
    `shadow-panel`, БЕЗ border — глубина светом, не обводкой. Раньше
    инструмент и соседний пояснительный блок статьи делили один и тот же
    `rounded-xl border bg-surface-container-low` — неотличимы; теперь у них
    разные визуальные языки (рамка+бледная подложка — контент статьи; тень+
    белая поверхность — сам инструмент).
  - `.result-hero` (новый класс) — единственный главный ответ экрана (число
    контраста, «At a glance» readability, «All formats» конвертера,
    сгенерированное заявление, сводка HTML-аудита). `bg-surface-elevated` +
    `shadow-hero` (самая сильная тень на странице), БЕЗ border, ровно один
    на экран — иначе теряет смысл геройского акцента.
  - `--color-surface-elevated: #ffffff` — контраст-безопасный по построению:
    `on-surface`/`on-surface-variant`/`primary` на белом дают СТРОГО больший
    ratio, чем на `background`(#fcf8fb)/`surface-container-low`(#f6f2f5) —
    контраст-гейт (`audit-a11y`) может от этого токена только улучшиться.
  - Под `prefers-reduced-motion: reduce` `.card` теряет `transition`
    целиком (интерполяция тени/цвета убрана, конечные состояния — те же),
    тот же принцип, что у `.stream-spinner`/`.modal-panel`/`.toast-item`.
  - Полный разбор узла — `docs/project/GRAPH.yaml` id `G-CHECKERS-ELEVATION`.
- Шапка — sticky + `bg-background/80` + `backdrop-blur-xl`.
- Карточки ≤ 3 колонок на десктопе (§26).

## 4. Фокус и интерактив

- Глобальное фокус-кольцо: `:focus-visible { outline: 2px solid
  var(--color-primary); outline-offset: 2px }` — на всём. `outline-none`
  запрещён.
- Поля — `.input` (pill) / `.input-area` (textarea); граница `outline` →
  `primary` при фокусе.
- Кнопки: `.btn` (primary pill, hover `--color-primary-hover` темнее —
  контраст в hover только растёт); `.btn-ghost` (outline pill). Подписи
  кнопок — label-md. Ссылки в тексте — underline.
- Один акцентный элемент на поверхность: primary CTA один на секцию; CTA шапки
  — secondary-container, не второй primary.

## 5. Severity-семантика в UI (карта применения)

- `ReportPage` findings: `chip chip-{impact}` — единственное место, где
  красный/оранжевый допустимы как фон-подложка.
- Legal-basis блок отчёта: family moderate — информация о праве, не severity;
  без сумм штрафов (D-035).
- Empty/success-состояния (§37) объясняют и ведут дальше; ошибки (§38)
  спокойные, конкретные, с путём вперёд (`scanErrorMessage`).

## 6. Чего НЕ делаем (§57 + D-035 + D-072, гейты)

- Градиенты, glassmorphism, неон, блобы, 3D, декоративный motion, автоплей.
- Fear-копия и суммы штрафов — нигде (гейт `no-fine-amounts.test.mjs`).
- Выдуманные счётчики и телеметрия — включая скопированные из макетов
  («SCANNING ENGINE ACTIVE», «99.8% Audit Accuracy», «142 agencies»): числа
  только из реальных данных сборки (D-035/D-045; отклонения — D-072).
- Второй акцент, перекраска severity брендом, иконки-декорации, второй
  икон-стиль. Иконочная система — одна: inline-SVG stroke (~1.5–1.75),
  `currentColor` (D-068); логотип-глиф — в ней же. Material Symbols и любые
  CDN-ресурсы (шрифты, скрипты) — НЕ подключаются (CSP, self-host, D-063).
- **Тёмной темы нет (D-073).** `@media (prefers-color-scheme: dark)` в
  `src/styles.css` не существует; сайт рендерит светлые токены независимо от
  системной темы посетителя. Была реализована полностью (D-072), убрана в
  тот же день прямым указанием владельца. Возврат — только новое решение
  владельца, не по умолчанию.

## 7. Верификация дизайна

Контраст палитры — не обещание, а гейт: `npm run audit-a11y` (axe, WCAG 2.2 AA
c явным `target-size`) — светлая тема, один проход по всему постоянному
сэмплу, 0 нарушений. При смене палитры чинится палитра, не проверка.
Скрипт-проверка пар токенов — scratchpad `contrast-d072.mjs` (одноразовая,
значения в таблице выше). Реверс тёмной темы (D-073) проверен живьём:
`emulateMedia({colorScheme:'dark'})` в Playwright против собранного `dist/` —
вычисленные `background-color`/`color` совпадают со светлыми токенами, а не
с прежними dark-значениями. Скриншоты D-072/D-073: scratchpad
`design/brand-light-*.png`, `design/home-light-only.png` (2026-08-08).
