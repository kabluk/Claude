## Lead Marketplace — предложение архитектуры (2026-08-14, PROPOSAL, ждёт решения владельца)

Владелец попросил разобрать механику подбора агентств под заявку на `/request-quote/`
и путь outreach, прежде чем проектировать дальше. Разведка кода (subagent) + разведка
аналогов (subagent, Angi/HomeAdvisor/Thumbtack/Clutch) — ниже синтез, решений НЕ
принято, код не менялся.

### Текущее состояние кода (уже есть, не гипотеза)

- `/request-quote/` (`RequestQuotePage.tsx`) → `LeadForm.tsx`. Кнопка «Preview matching
  agencies» **не шлёт сеть** — только клиентский `matchAgencies()` (`src/lib/
  matchAgencies.ts`): фильтр country → service → standard (из закона страны) → priceBand
  как мягкий тайбрейкер (не фильтр, т.к. заполнен у горстки профилей) → до 5 карточек.
  Явный баннер «nothing was submitted anywhere».
- `POST /api/lead` (`worker/routes/lead.js`) **полностью готов и НЕ используется**:
  валидация, Turnstile, rate-limit 5/ч/IP, тот же алгоритм матчинга на сервере
  (`matchAgenciesServer.js`), запись лида в D1 (`leads`), best-effort email
  **только claimed+verified** агентствам (Resend) — не всем матчам.
  Единственный блокер подключения: у `LeadForm` нет `<TurnstileWidget>` (есть у
  ScanForm/SubscribeForm) — без него submit получит 403, раз `TURNSTILE_SECRET_KEY`
  на воркере уже стоит (D-140/D-169).
- Верификация уже есть (`claims` table, email-подтверждение) — де-факто Clutch-style
  verified badge, просто не подписана так в UI лид-формы.

### Что подтвердили аналоги

- **Никто не блюрит identity поставщика** (Angi/HomeAdvisor/Thumbtack/Clutch) — везде
  открытое название компании, скрывают только прямой контакт до явного действия юзера.
  Наш `AgencyCard` уже открытый — менять не нужно.
- **Cold-start = supply-first + курируемая верификация**, не blind auto-broadcast с
  первого дня (паттерн индустрии) — совпадает с уже принятым «лиды агентствам в фазе 1
  бесплатны, cold-start». Наш фильтр-матчинг + email только claimed+verified уже
  структурно ближе к «curated», чем к blind broadcast (HomeAdvisor шлёт shared-лид
  3–8 подрядчикам без разбора).
- **Angi после перехода blind-broadcast → user-choice (янв 2025): NPS +11, win-rate
  подрядчиков +60%.** Довод в пользу текущей узкой модели (≤5 релевантных карточек,
  не веерная рассылка).
- **Clutch verified badge** закрывает trust-gap без истории отзывов — прямое
  переиспользование нашего claim+verify, нужно явно вывести в UI как «Verified».

### Развилки — нужно решение владельца, ДО кода

1. **Подключить `LeadForm` → `/api/lead` сейчас?** Backend полностью готов; работа —
   добавить `<TurnstileWidget>` (тот же паттерн, что уже дважды использован) + реальный
   `fetch` вместо no-op на втором шаге формы. Небольшая, хорошо очерченная задача.
2. **Что показывать в preview, если матч НЕ claimed/verified?** Сейчас клиентский
   preview показывает их наравне с claimed, но письмо сервер шлёт только
   claimed+verified — в тонких юрисдикциях лид может «уйти в никуда» (карточка в
   preview есть, письмо никто не получит). Варианты: (A) помечать unclaimed в preview
   явно + карточка становится growth-loop приглашением агентству «claim this listing»;
   (B) фильтровать preview только claimed+verified (честнее, но 0–1 карточка вместо 5
   в тонких странах).
3. **Эксклюзивность лида.** Сейчас сервер шлёт письмо ВСЕМ claimed+verified из top-5
   match, без лимита получателей (de facto shared, как HomeAdvisor). Кандидат — оставить
   так на фазе 1 (бесплатно, растим track record), пересмотреть в фазе 2 монетизации.
4. **Outreach: автоматика или курируется?** Текущий код уже автоматический (best-effort
   email при сабмите, без ручного шага). Если владелец хочет ручной review лидов на
   старте (мало проверенных агентств) — нужен новый узел (staging перед отправкой).
   Если устраивает автоматика — можно просто подключить готовый код.

### Рекомендация (research-based, не решение)

Механика уже спроектирована близко к тому, что работает у аналогов — curated
filter-matching + verified badge вместо анонимного blur или дорогого auction/reverse-
marketplace. Самый дешёвый следующий шаг — подключить уже готовый `/api/lead` (п.1),
явно решив п.2 заранее (не удивляться в проде «лид ушёл, ответа нет»). Полноценная
Thumbtack-style reverse-marketplace (конкурирующие quote'ы, встроенный мессенджер) —
явно избыточна для фазы 1, кандидат для фазы 2 монетизации.
