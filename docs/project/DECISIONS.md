для естественной самопроверки продукта (D-011, `audit-a11y`), `review` ≠ `done`
для частично проверенных узлов (D-010, A1-SCAN). Последствия: будущие сессии этого
проекта наследуют не только правила, но и опыт; изменения в `.claude/commands/`
и `.claude/agents/` впредь фиксировать здесь же кратким пунктом.

## D-011 · 2026-08-05 · accepted
UX была сквозным пробелом: ни в одном файле `docs/project/` не было ни слова про
UX/дизайн, хотя воронка Scan→...→Dashboard (VISION.md) — это конверсионная цепочка,
где качество опыта на каждом шаге прямо определяет выручку Фазы 2. Найдено по
прямому вопросу владельца после повторного показа скриншота с воронкой.
Решение: (а) `frontend-engineer` явно берёт UX/UI-дизайн на себя — в ролях
`claude-project-orchestrator` нет отдельной UX-роли, и это не должно молча
означать «дизайн никто не делает»; (б) 5 обязательных требований записаны в
VISION.md как приёмочные критерии для A1-REPORT/A1-LANDING/A1-COST, не просто
пожелания; (в) самопроверка сайта axe-core закреплена постоянным CI-гейтом
(`scripts/audit-own-a11y.mjs`, `npm run audit-a11y`), а не разовым обещанием —
запущена в этой же сессии: 21 страница / 14 шаблонов, 0 нарушений на сейчас.
Последствия: RISKS.md R12, ROADMAP.md Фаза 1 получает явный UX-критерий выхода.

## D-010 · 2026-08-05 · accepted
A1-SCAN реализован (`worker/`, `wrangler.jsonc`, `migrations/0001_init.sql`) с
уточнениями относительно черновика в INTERFACES.md:
- `ScanReport` дополнен полями `status`/`error`/`completedAt` — `POST /api/scan`
  асинхронный (202 сразу, работа идёт в `ctx.waitUntil`), клиенту нужно различать
  running/done/error при поллинге `GET /api/scan/:id`.
- axe-core инжектится как **content-script** (`page.addScriptTag({content: ...})`),
  а не через `src=CDN` на самой целевой странице — иначе строгий CSP на чужом сайте
  (`script-src`) заблокирует загрузку. Источник axe-core кэшируется в edge Cache API
  на 7 дней, версия зафиксирована (4.10.2), не берётся «latest».
- Score — эвристика с дедупом по `ruleId` (худшая severity среди инстансов страницы),
  не по количеству найденных нод. Иначе одна системная проблема (alt-текст на 40
  картинках) обнуляла бы счёт так же сильно, как 40 разных проблем. Чистая функция
  `worker/lib/score.js`, юнит-тесты в `score.test.mjs`.
- `worker/` — plain ESM JS, не TypeScript: проект уже написан без TS-тулчейна для
  `scripts/*.mjs`, отдельный `tsconfig.worker.json` + `@cloudflare/workers-types`
  добавили бы toolchain-сложность без пропорциональной пользы для MVP.
- Верификация в этой сессии: routing/валидация/D1 read-write/KV rate-limit/`ctx.waitUntil`
  error-handling — проверены live через `wrangler dev` (реальные HTTP-запросы, реальная
  локальная D1/KV). Локальный Browser Rendering реально скачал и запустил Chromium
  (после `CI=true`, снимающего `--no-sandbox`-ограничение контейнера), дошёл до
  `page.goto()` — но упёрся в MITM-прокси песочницы (`/root/.ccr/README.md`),
  которому локальный Chromium не доверяет, поэтому сама инъекция `axe.run()` против
  реального сайта не подтверждена в этой сессии. Ограничение среды разработки, не
  кода: у настоящего Cloudflare Browser Rendering в проде прямой выход в интернет.
  Требуется один прогон `wrangler dev --remote` или прод-деплой на реальном аккаунте
  владельца перед тем, как считать узел полностью verified.

## D-009 · 2026-08-05 · accepted
`ci.yml` на ветке `accessatlas` был скопирован из `main` (detnav) целиком, включая
`lint:upl`/`lint:minimize` — линтеры юридического контента (сканируют `content/**`
на формулировки вида «вам следует», «ваши шансы», риск unauthorized practice of law
для detnav's habeas/attorney/deadlines-контента). У AccessAtlas нет `content/` и
юридико-консультационного контента такого типа — эти два шага удалены из `ci.yml`
как неприменимые, не переписаны заглушками. `check-links.mjs` — иначе: генерик-идея
(все внутренние href резолвятся в существующие файлы dist/), полезна и для
AccessAtlas, реализована заново под структуру этого сайта (413 ссылок, 0 битых) и
добавлена в `package.json` как `npm run check-links`. Последствия: CI на ветке
снова проходит от `npm ci` до сборки без вымышленных шагов.

## D-005 · 2026-08-05 · proposed
AI-пояснения находок — Claude Haiku через Worker; кэш по `ruleId × locale` в KV.
Причина: пояснение зависит от типа правила, а не от конкретного сайта → 95%+ попаданий

бюджетный лимит и rate-limit.

## D-004 · 2026-08-05 · proposed
Сканер — Cloudflare Worker + Browser Rendering + axe-core; результаты в D1; отчёт по
приватной ссылке `/report/:id` (noindex). Главная + до 5 страниц из sitemap за скан.

маппингом на WCAG. Последствия: лимиты Browser Rendering — при росте вынести в Queues.

## D-003 · 2026-08-05 · accepted
Продукт развивается по модели **Directory → Decision Engine → Lead Marketplace →
Vertical SaaS**; целевая воронка: Scan → Report → AI explains → Cost → Compare →
Book → Track → Re-scan → Dashboard. Причина: каталог-список легко заменить AI;
платформа в рабочем процессе клиента — нет. Последствия: ROADMAP перестроен на 4 фазы;
сканер — приоритет сразу после запуска каталога.
