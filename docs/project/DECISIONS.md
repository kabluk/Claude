# DECISIONS — журнал решений

Формат: ID | дата | решение | причина | последствия. Новые решения добавлять сверху.
Статусы: `accepted` (принято), `proposed` (ждёт подтверждения владельца).

## D-008 · 2026-08-05 · accepted
Управление проектом — по claude-project-orchestrator: память в `docs/project/`,
граф задач в `GRAPH.yaml`, узлы через `/task-loop`, handoff между сессиями.
Причина: проект многодоменный, одна длинная сессия переполняет контекст.
Последствия: каждая итерация обновляет STATUS/BACKLOG/HANDOFF; агенты возвращают
компактные контракты, детали пишут в domains/*.md.

## D-007 · 2026-08-05 · accepted
Порядок монетизации: сначала featured/claim-outreach (Фаза 2 начало), затем лидоген,
затем подписка SaaS. Причина: outreach по своей базе не требует трафика — выручка
возможна с месяца 2–3 (deepdive §5). Последствия: claim-поток приоритетнее RFQ.

## D-006 · 2026-08-05 · proposed
Оценка стоимости исправлений — клиентская эвристика: находки × тяжесть × размер сайта
× price bands из `taxonomies.json`, всегда вилкой и с дисклеймером «оценка, не оферта
и не юридическое заключение». Причина: честность и юр-безопасность; точных цен в данных
пока 4/253. Последствия: нужен бенчмарк цен (Growth) для сужения вилок.

## D-005 · 2026-08-05 · proposed
AI-пояснения находок — Claude Haiku через Worker; кэш по `ruleId × locale` в KV.
Причина: пояснение зависит от типа правила, а не от конкретного сайта → 95%+ попаданий
в кэш, стоимость ≈0, ключ API не утекает на клиент. Последствия: нужен секрет в Worker,
бюджетный лимит и rate-limit.

## D-004 · 2026-08-05 · proposed
Сканер — Cloudflare Worker + Browser Rendering + axe-core; результаты в D1; отчёт по
приватной ссылке `/report/:id` (noindex). Главная + до 5 страниц из sitemap за скан.
Причина: остаёмся в одном стеке (Cloudflare), axe-core — отраслевой стандарт с
маппингом на WCAG. Последствия: лимиты Browser Rendering — при росте вынести в Queues.

## D-003 · 2026-08-05 · accepted
Продукт развивается по модели **Directory → Decision Engine → Lead Marketplace →
Vertical SaaS**; целевая воронка: Scan → Report → AI explains → Cost → Compare →
Book → Track → Re-scan → Dashboard. Причина: каталог-список легко заменить AI;
платформа в рабочем процессе клиента — нет. Последствия: ROADMAP перестроен на 4 фазы;
сканер — приоритет сразу после запуска каталога.

## D-002 · (ранее) · accepted
AccessAtlas живёт standalone-веткой `accessatlas` в репо `kabluk/Claude`; в `main` —
несвязанный проект detnav. Последствия: рабочие ветки создаются от `accessatlas`,
не от `main`; при желании выносится в отдельный репозиторий.

## D-001 · (ранее) · accepted
Static-first: источник истины — плоские JSON в `data/a11y/`, сайт генерируется
`vite-react-ssg`, никакой БД для чтения. Динамика — только Workers + D1 + KV.
Последствия: каталог не зависит от динамики; деградация изящная.
