## 0. Как начать новую сессию

Скажите Claude ровно это:

> Работай в ветке `accessatlas`. Прочитай research/STATE.md и продолжи проект AccessAtlas.

Указание ветки в первой строке обязательно — проект живёт в ветке `accessatlas`,
в `main` его нет. Дальше проверьте, что среда жива:


Если нужны внешние API — см. §6 «Инфраструктура и ключи».

## 1. Что это за проект

Мультиязычный каталог агентств аудита цифровой доступности (EAA / WCAG / ADA / BFSG / RGAA).
Ниша выбрана после исследования 150+ кандидатов, подтверждена живыми SERP-замерами и DataForSEO:
**спрос ≈45 000 запросов/мес по 8 рынкам**, ни одного каталога в топ-10 ни по одному ключу, CPC до $86.
Оценка ниши: **7.9/10, вердикт «строить»**. Полное обоснование: `docs/deepdive-accessibility-directory.md`.

Проект называется **AccessAtlas** и живёт в ветке `accessatlas` репозитория `kabluk/Claude`
как самостоятельное приложение (в корне). В `main` — другой, несвязанный проект (detnav);
общей истории у них нет. При желании AccessAtlas выносится в собственный репозиторий.

## 2. Честный статус готовности

Проект **не готов к запуску**. Построено много, но три рубежа не пройдены.

### Рубеж 1 — «можно показать людям». Частично пройден.
| Что | Статус |
|---|---|
| Домен | ❌ заглушка `accessatlas.example` в 2 файлах (см. §5) |
| Деплой-конфиг | ❌ нет (нужен свой для Cloudflare Pages / Netlify) |
| About / Contact | ✅ есть (`AboutPage.tsx`, `ContactPage.tsx`), в футере на каждой странице |
| Privacy Policy | ✅ есть, честная (в кодовой базе проверено: нет аналитики/куки/форм — написано только то, что подтверждено) |
| Imprint | 🟡 страница есть, но **юр. реквизиты (юрлицо/адрес/регистрация) не выдуманы** — placeholder, `index=false`, ждёт данных владельца. Блокер для запуска на DE/EU, пока не заполнено |
| 404-страница | ✅ есть, плюс `dist/404.html` в корне (конвенция Cloudflare Pages/Netlify) |
| Иерархия заголовков | ✅ исправлено — все страницы (383/383) проверены скриптом, h1→h3 без h2 больше не встречается |

### Рубеж 2 — «можно индексировать без вреда». НЕ пройден.
| Поле | Заполнено |
|---|---|
| Описание профиля | **81 / 254 (31%)** ← главная дыра |
| Город | 153 / 254 (60%) |
| Ценовой диапазон | 4 / 254 (1%) |
| Сертификация | 124 / 254 (48%) |
| ≥2 источника | 179 / 254 (70%) |

173 профиля — это название, домен и ссылка на декларацию. Порог ≥3 листинга защищает
списочные страницы от thin-content, но **не защищает профили**. Массовая индексация в таком
виде — риск.

### Рубеж 3 — «можно зарабатывать». НЕ начат.
Лид-форма, claim-поток, Stripe — **ничего не построено**. После деплоя выручка физически невозможна.

### Что действительно готово
- 254 агентства, 21 страна, схема валидируется, дубликатов нет
- 12 редакционных гайдов с фактчекингом по первоисточникам
- 383 статических страницы, JSON-LD (ProfessionalService / ItemList / Article / FAQPage / BreadcrumbList)
- About, Contact, Privacy, 404 — реальный контент, не заглушки; Imprint — честно помечен как неполный
- Клиентские фильтры, работающие поверх SSG (без JS список виден целиком)
- Иерархия заголовков корректна на всех 383 страницах (проверено скриптом, не выборочно)
- noindex,follow ниже порога ≥3; sitemap 350 URL без noindex-страниц (Imprint/404 исключены)
- Воспроизводимый конвейер данных: сбор → слияние → обогащение → валидация → сборка

## 4. Команды

```bash
# Данные
node scripts/build-a11y.mjs              # валидация + генерация индексов
node scripts/build-a11y.mjs --strict     # + все замечания о неполноте (сейчас ~700)
node scripts/merge-a11y.mjs --dry        # предпросмотр слияния сборщиков
node scripts/merge-a11y.mjs              # слить
node scripts/enrich-a11y.mjs --dry       # предпросмотр обогащения
node scripts/enrich-a11y.mjs             # применить патчи

# Сайт
npm run dev                    # дев-сервер
npm run build                  # данные → 383 страницы → sitemap (в dist/)
```

Порядок при добавлении данных: положить файл в `collect/` → `merge-a11y.mjs` → `build-a11y.mjs` → `npm run build`.

   Сейчас интерфейс только английский, мультиязычны лишь гайды.

## 6. Инфраструктура и ключи

- **DataForSEO** — логин `zincroom@gmail.com`, баланс ~$525. Пароль в переменных окружения
  (`DATAFORSEO_LOGIN`, `DATAFORSEO_PASSWORD`), **в репо не хранится**.
  Требует разрешённый домен `api.dataforseo.com` в network access.
  Проверка: `node scripts/seo-data.mjs balance`
- **Firecrawl** — ключ выдавался в чате, **в репо и в env не хранится**. При необходимости
  сообщить Claude заново. Расход на этап деклараций — ~2600 кредитов.
- **Открытый вопрос:** у DataForSEO запрошен возврат $475 излишнего депозита; после этого
  сбросить API-пароль (засветился в чате) и обновить переменную окружения.

## 7. Хронология

| Этап | Результат |
|---|---|
| Исследование ниш | 150+ кандидатов → 7 blue-ocean → выбран каталог доступности (7.9/10) |
| Дни 1–2 | Схема данных, таксономии, конвейер сборки |
| Дни 3–3.5 | 4 агента собрали 152 агентства (BITV, IAAP, конференции, UK, US, EU) |
| Дни 8–12 | MVP-сайт: 258 страниц, JSON-LD, фильтры, порог индексации |
| Дни 13–20 | 12 гайдов + инфраструктура гайдов |
| Дни 4–7 | Обогащение: +54 города, +111 описаний, +196 полей, +144 источника |
| Дни 24–27 | **+99 агентств из деклараций гос-сайтов ЕС** — защищаемый датасет |

Ключевые находки этапа деклараций: реестр NL не называет аудитора («независимая третья
сторона»), имена пришлось добывать из 1569 PDF-отчётов; польские декларации следуют жёсткому
шаблону и собираются регуляркой; Италия и Испания структурно бедны — их формы либо не называют
аудитора, либо фиксируют самооценку.

**Запасная ниша №2** (если эта не пойдёт): DGSA / опасные грузы ЕС — балл 8.1, но трафик дешевле.
