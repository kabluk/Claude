# Loop Engineering — проектирование самоусиливающихся циклов роста и удержания

Материалы для этапов 2, 6 и 7. Суть техники: рост продукта проектируется не как линейная воронка (трафик → signup → оплата), где каждый пользователь куплен заново, а как **замкнутый цикл**, где выход одного оборота становится входом следующего. Воронка тратит ресурс, цикл его воспроизводит. Loop engineering — это осознанное конструирование таких циклов как фич продукта, а не маркетинговых активностей "потом".

## 1. Анатомия цикла

Каждый цикл описывается четырьмя шагами. Заполни шаблон для каждого проектируемого цикла:

```
1. Вход      — кто/что запускает оборот (новый пользователь, действие существующего)
2. Действие  — что делает пользователь внутри продукта
3. Выход     — какой артефакт/сигнал порождает действие (контент, инвайт, данные, результат)
4. Возврат   — как выход приводит новых пользователей или возвращает существующих на шаг 1
```

Цикл существует, только если шаг 4 замыкается на шаг 1 **без ручного участия основателя**. "Я напишу пост о фиче" — не цикл. "Каждый созданный пользователем отчёт имеет публичную ссылку с CTA" — цикл.

Два числа определяют силу цикла:
- **Коэффициент усиления (amplification)** — сколько новых входов даёт один оборот. Для acquisition-циклов это viral coefficient K: приглашений на пользователя × конверсия приглашения. K = 0.3 уже отлично для B2B (каждые 10 клиентов бесплатно приводят 3).
- **Время оборота (cycle time)** — сколько дней проходит от входа до возврата. Цикл с K=0.2 и оборотом 3 дня сильнее цикла с K=0.4 и оборотом 60 дней. Сокращение времени оборота почти всегда дешевле, чем повышение K.

## 2. Четыре типа циклов (выбирай 1–2, не все)

### Acquisition loop — пользователи приводят пользователей

- **Механики:** артефакт продукта виден наружу (публичная страница, embed, badge "Made with X", шаринг результата); коллаборация требует пригласить коллегу (документ, борд, проект); реферальная программа (двусторонняя выгода).
- **Подходит:** продуктам, чей выход — что-то, что показывают другим (документы, страницы, отчёты, дизайны), и командным инструментам.
- **Метрики:** K-фактор, % оборотов с ≥1 приглашением/шарингом, конверсия просмотра артефакта в signup.

### Content loop — использование порождает индексируемый контент

- **Механики:** пользовательский контент становится публичными SEO-страницами (профили, шаблоны, вопросы-ответы, галереи); программные страницы из данных продукта.
- **Подходит:** продуктам с UGC или структурированными данными; горизонт — медленный (3–9 месяцев до эффекта), зато компаундится.
- **Метрики:** число проиндексированных страниц, органический трафик → signup, время оборота (публикация → первый визит из поиска).

### Engagement loop — привычка возвращаться (модель Hooked)

```
Триггер (внешний → внутренний) → Действие → Переменная награда → Инвестиция
```

- **Механики:** триггер — уведомление/дайджест/событие в данных пользователя ("ваш отчёт готов", "коллега прокомментировал"), которое со временем замещается внутренним ("надо глянуть метрики"); инвестиция — каждый оборот пользователь вкладывает что-то, что делает следующий оборот ценнее (данные, настройки, история, подписки на объекты).
- **Подходит:** всем. Это главный цикл для retention — проектируй его всегда, даже если acquisition-цикла нет.
- **Метрики:** retention D7/D30 (см. launch-and-iterate.md), % пользователей с включёнными триггерами, глубина инвестиции (объём накопленных данных/настроек на пользователя).

### Monetization loop — деньги реинвестируются в рост

- **Механики:** выручка → предсказуемый платный канал (реклама, контент, sales) с окупаемостью CAC < 3–6 месяцев → новые платящие → выручка.
- **Подходит:** после PMF. До PMF платный цикл на дырявом retention — сжигание денег (см. критерии в launch-and-iterate.md).

## 3. Процесс loop engineering по этапам

### Этап 2 (Scoping) — спроектируй цикл на бумаге

1. Заполни шаблон из раздела 1 для одного acquisition- или content-цикла и одного engagement-цикла.
2. Проверь тест естественности: цикл должен усиливать Core Job, а не мешать ему. Принудительный шаринг ради шаринга ("пригласи 3 друзей, чтобы открыть фичу") убивает доверие — пользователь делится, потому что артефакт полезен получателю.
3. Реши, что из цикла входит в MVP scope. Минимум: артефакт главного сценария должен иметь публичную ссылку/embed с ненавязчивым CTA, а схема данных — поддерживать "инвестицию" (история, накопление). Полная реферальная программа — почти всегда "после запуска".

Спроси пользователя:
- "Что из результатов работы в продукте пользователь мог бы показать коллеге или клиенту? Как сделать это показывание однокликовым?"
- "Что накапливается у пользователя с каждым использованием, из-за чего уходить будет жалко?"
- "Какое событие в данных пользователя — честный повод отправить ему уведомление?"

### Этап 6 (Launch) — инструментируй обороты

1. Добавь события каждого шага цикла в PostHog (вход → действие → выход → возврат) — иначе цикл нельзя ни измерить, ни улучшить.
2. На консьерж-созвонах смотри, замечают ли пользователи механику шага "выход" сами. Если приходится объяснять — механика спрятана или неестественна.
3. Считай базовые числа на когортах soft launch: % оборотов, доходящих до шага 4; время оборота; K-фактор (если acquisition-цикл).

### Этап 7 (Iterate) — оптимизируй самое слабое звено

1. Раз в неделю смотри funnel цикла и находи шаг с максимальным отвалом — эксперимент Build-Measure-Learn направляй туда, а не равномерно по всему циклу.
2. Порядок рычагов: сначала конверсия слабейшего шага → потом время оборота → потом K. 
3. Не добавляй второй цикл, пока первый не крутится сам: признак — метрики цикла растут неделя к неделе без ручных действий основателя.

## 4. Анти-паттерны

- **Цикл до валидации.** На этапе 1 никакого loop engineering — сначала докажи, что Core Job нужен. Цикл усиливает то, что есть; усиливать ноль бессмысленно.
- **Виральность как оправдание слабого retention.** Если D30 < 20%, acquisition-цикл наливает воду в дырявое ведро — сначала engagement-цикл.
- **Копирование чужого цикла без своего артефакта.** "Сделаем реферальную программу как у Dropbox" не работает, если продукту нечем естественно делиться. Тип цикла выводится из Core Job, не из кейсов.
- **Тёмные паттерны** (спам-инвайты по контактам, шаринг без ведома пользователя, накрутка уведомлений). Дают всплеск метрик на недели и репутационную яму навсегда.
